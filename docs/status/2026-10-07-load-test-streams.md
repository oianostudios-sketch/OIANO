**The load test holds live streams through its request mix and times live updates on every one, 2026-10-07.** Reconciliation C36: `apps/api/scripts/load-test.js` opened its SSE connections only after the booking burst had finished, drained them without reading an event, and counted only how many opened. It could not say whether a held stream ever heard anything, how long the first event took, or whether an update reached the audience under load. It also refused localhost, so it could be run only against a remote deploy.

- **What changed.** The streams open first and are held through the booking and pulse bursts. Each stream's events are parsed (`createSseParser`), recording time to the `connected` event. While the bursts run, the script posts a studio announcement every `SSE_PROBE_INTERVAL_SEC` (default 10s), plus one after the bursts. These are probes titled `load-test probe <n>`, and the script times their arrival on every held stream. `summarizeStreams` reports connections requested, established, failed, dropped before the end and held to the end. It reports time to first event as p50, p95 and max, and the probes as owed, delivered and missed, latency p50, p95 and max, `reachedEveryHeldStream`, and the accounts that heard no probe. A stream is owed a probe only when it was open when the probe went out. If it drops after that without hearing the probe, the probe counts as missed. A probe the limiter rejects waits out the window and records how long (`rateLimitedMs`); `PROBE_EMAIL`/`PROBE_PASSWORD` can name a second studio admin so probes do not share the pulse phase's budget. Target: the default is `http://localhost:4000` (`--target=` or `TARGET_URL` set it). Any other host needs `--allow-remote`, and a host containing `prod` also needs `--i-know-this-is-production` (`resolveTarget`). No new dependency.
