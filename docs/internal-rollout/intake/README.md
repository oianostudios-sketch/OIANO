# Creative intake round

How to collect each person's own description of their work, and turn it into
decisions without guessing from job titles. Task T01 in `../BACKLOG.md`; this folder
supersedes the single-page `../CREATIVE_INTAKE.md` as the working method, which stays
for history.

| File | For | Use |
|---|---|---|
| [QUESTIONNAIRE.md](QUESTIONNAIRE.md) | Participants | Send as is, or use as a conversation guide |
| [RECORD_TEMPLATE.md](RECORD_TEMPLATE.md) | Interviewer | One private record per person and example |
| [CURRENT_SUPPORT.md](CURRENT_SUPPORT.md) | Whoever maps answers | What OIANO does today, per primitive, with code references |
| [SYNTHESIS.md](SYNTHESIS.md) | Owner and builders | Anonymised patterns and the route for each finding |

Use the [first-five checklist](../FIRST_FIVE_CHECKLIST.md) for the invitation draft,
account limitations and the evidence required before real use. Intake itself does
not require an account or approval to start a live pilot.

## Privacy first

This repository is public. **Completed questionnaires, notes, voice notes and records
never go in it**, nor do participants' names or client details. Keep them in one
private place the owner chooses and controls (for example a private folder or private
document), named only in that place. Only anonymised patterns, by record id, move into
`SYNTHESIS.md`. Ask each person's consent before keeping their answers, and delete them
on request.

## Who first

Start with five people, one real recent piece of work each. Together they cover the
studio baseline and the disciplines the current system fits least:

1. One producer: the person who leads work today; establishes the baseline.
2. The poet: text, performance and publication; no studio needed.
3. One cinematographer: locations, large files, cuts and review.
4. Studio management: rooms, staff, scheduling and studio terms.
5. One artist who also uses other studios.

Then the second cinematographer (to see what is personal versus shared within one
discipline), and models when a real piece of work involves them, where permission over
their image is the key question.

## Running each one

1. Send the questionnaire, or book 30 to 45 minutes and talk through it.
2. Get one concrete example. If they generalise, ask "on that piece, what happened?"
3. Use their words. Do not offer OIANO terms or suggest answers; ask "then what?",
   "who decides?", "what gets passed along?"
4. Fill a private record from RECORD_TEMPLATE.md: the **Told** column only, then
   **Today** from CURRENT_SUPPORT.md.
5. Write the **Proposed** column, and show it back to them in plain language within a
   week. Record their answer and date in **Confirmed**. Corrections win.
6. Agree any temporary limitation for the pilot in plain words and record it.

An agent can help with steps 4–5 if the owner shares a transcript in a session; the
agent must not write it into the repository.

## From answers to decisions

After three confirmed records, fill `SYNTHESIS.md` and give every finding one route:
supported, temporary agreement, small fix, canonical step, or more intake. Bring the
small fixes to the owner as a proposed batch. Canonical-step findings feed that step's
design in the frozen order; they are not built early.

Likely first candidates, **to be confirmed by the records, not assumed**: truthful
contributor role labels; missing disciplines in the profile list (writer or poet,
cinematographer, model); a depicted person answering their own usage consent; work
delivered outside a studio booking.

## Done when

- At least five records exist privately, each with its proposals shown and answered.
- `SYNTHESIS.md` has the shared concepts, differences and a route for each finding.
- Each pilot participant's temporary agreements are recorded.
- The owner has a proposed next batch drawn from the synthesis.
